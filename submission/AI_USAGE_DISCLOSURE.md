## 7. Known Limitations and Areas Requiring Further Improvement

I am disclosing these honestly:

1. **In-memory generation:** The generator holds all data in memory before exporting. For production use at millions-of-records scale this would need to be refactored as a streaming pipeline.

2. **Simplified tax modeling:** Net income uses empirical 72–80% withholding brackets, not jurisdiction-specific tax schedules. This affects the realism of income records.

3. **Day-count convention:** Amortization schedules assume uniform 30-day months rather than Actual/Actual or 30/360 convention. Real-world loan schedules use precise calendar dates.

4. **No live database:** Data is exported as flat CSV/JSON/SQL files. A production system would use a relational database with real DDL constraints enforced at write time.

5. **Fair lending guardrail is an architectural guardrail, not a legal certification:** The implementation structurally excludes protected demographic attributes from underwriting inputs. This is a software design control, not a regulatory compliance assessment under ECOA, Reg B, or any other statute.

6. **I did not write the code independently:** The code in this repository was generated by AI based on the prompts I provided. I reviewed the outputs, identified gaps, specified corrections, and verified results using the test suite and validation commands. I did not write the Python source files myself line by line.

7. **ChatGPT prompt history recovery is pending:** ChatGPT conversation logs were not automatically captured in a machine-readable IDE transcript. Prompt recovery is pending candidate review of account data export files and web conversation history. See Part B of `AI_PROMPT_HISTORY.md` for details.
